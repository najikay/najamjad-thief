survive 35 — expected since our thief now outlasts our own cop).

**The defect it found (T-2708) had defeated the whole merge.** `await_partial`
refused a live half-series as "stale" and filed a two-game series as one game —
precisely the rules 33-35 mismatch the module exists to prevent. The freshness
test compared the sibling's half against our own first mini-game's start, and
that assumption is false in exactly the arrangement it was written for: **the
two halves are independent streams**. Our thief opened window 1, played it and
wrote its half at 20:02:01 while our own server had not finished binding until
20:02:07. Moving the line back to this process's start failed the same way, for
the same reason.

So no clock decides it any more. Each process **deletes its own halves** as its
series starts (`sibling_merge.clear_partials`, called from `actions.play_match`
and nowhere earlier — `preflight` and `peer` build the same runner, and clearing
there would delete a half the sibling is waiting to merge). Whatever is found
under the sibling's role was written by the sibling's current run. Rule 2 is
untouched: each process only ever deletes what it wrote itself.

## 3. Playing a split series — the commands

Both terminals get the **same** `--opens` value: it names *our group's* role in
mini-game 1, not the process's. Disagreement is silent and expensive — both
would claim window 1 and neither would play window 2. Compare the
`series.role_split` line in the two terminals before dialling.

```bash
# 1. cards (writes into BOTH repos) — re-card ali-ahm1 immediately before
#    playing, their free-tier ngrok URLs rotate on every restart
uv run python scripts/match_day.py card --team <name> --url <their-url> \
    --group-id <their-exact-group-id>

# 2. arm
uv run python scripts/match_day.py warmup     # sandbagged + draft
uv run python scripts/match_day.py counted    # full + send

# 3. BOTH tunnels, own terminals, left running
cloudflared tunnel run --url http://127.0.0.1:8802 najamjad-cop
cloudflared tunnel run --url http://127.0.0.1:8801 najamjad-thief

# 4. preflight in each repo, then play — one terminal each
uv run najamjad-thief preflight --opponent <their-cop-card> --practice
uv run najamjad-cop    preflight --opponent <their-thief-card> --practice

# opening as THIEF (we take 1/3/5 in the thief repo):
uv run najamjad-thief match --opens thief --opponent <team>-cop --no-tunnel --practice --talk
uv run najamjad-cop   match --opens thief --opponent <team>     --no-tunnel --practice --talk
```

**Which card goes in which terminal.** `<team>.toml` holds their **thief** door
and belongs to `najamjad-cop`; `<team>-cop.toml` holds their **cop** door and
belongs to `najamjad-thief`. Our cop only ever faces their thief, whichever role
we open in. Picking the wrong one sends window 1 to a process not expecting it.

Only the process holding the **last** window files; the other writes its half to
`workspace/partials/` and exits. Expect `series.rejoined sub_games=[1..6]` in
the filing terminal. Then, for a counted series,
`uv run python scripts/reconcile_counted.py ../<sibling> --apply`.

**Both dashboards bind port 8000**, so with two processes only the first gets
one — the second's server thread dies quietly and never touches the game. Run
`--dashboard` on one terminal only until a `--dashboard-port` flag exists.

### The split needs the opponent to be split too

Their two processes must each hold *our* counterpart door: their cop dials our
thief, their thief dials our cop. Automatic for a peer split as we are — which
both moaamoha and ali-ahm1 say they are. A peer running **one** process holds
one `opponent_url` for the whole series and never retargets (the course
reference builds its client once and cannot), so three of our six windows would
arrive at the wrong door. Against such a peer, leave `--opens` off and play
unsplit, exactly as the three counted series were played.
