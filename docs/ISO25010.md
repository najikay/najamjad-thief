# ISO/IEC 25010 quality mapping

**Version 1.00 · 2026-07-27**

The eight product-quality characteristics of ISO/IEC 25010, each mapped to
concrete evidence in this repository — a test, a gate, or a document. Where the
evidence is weak, this document says so rather than filling the row.

A mapping like this is easy to write as eight paragraphs of assertion. The rule
followed here is that **every row names something a reader can open and check**,
and rows we cannot evidence are marked ⚠ rather than argued for.

---

## 1. Functional suitability

*Completeness, correctness, appropriateness.*

| Sub-characteristic | Evidence |
|---|---|
| Completeness | All four mandated MCP tools implemented and asserted present: `tests/integration/test_interop_contract.py`. `scripts/check_all.py` fails if a mandated file is missing. |
| Correctness | 1,600+ tests; 99.3 % line coverage. Game rules are tested against the book's numbered rules, cited by number in the test names. |
| Appropriateness | The strategy is measured, not asserted: 60/60 captures against the greedy baseline on held-out games (`notebooks/analysis.ipynb` §4). |

**The strongest single piece of evidence is negative.** Three defects survived
1,500 passing tests because the fakes were kinder than the wire. Functional
suitability against *our own model* of the protocol was never in question; it
was suitability against a stranger's that failed. `tests/integration/test_interop_contract.py`
exists because of that, and it tests against the reference's shapes rather than
ours.

## 2. Performance efficiency

*Time behaviour, resource utilisation, capacity.*

| Sub-characteristic | Evidence |
|---|---|
| Time behaviour | Move latency asserted **< 5 s on a 15×15 board** — far larger than the negotiated 7×7 — against a 30 s response budget (`tests/unit/test_scripts/test_quality_gates.py`). Transport measured at 12 ms per message. |
| Resource utilisation | Token consumption **measured**, not estimated: 4,577 per series, 2.3 % of the agreed cap (`docs/TOKEN_BUDGET.md`). |
| Capacity | Three consecutive series drain their queues to zero and the event log does not degrade as it grows (`tests/integration/test_chaos_services.py`). |

One measured regression is worth recording: the event bus reopened its file per
event, costing 14 ms per write on a Windows-mounted filesystem. Holding the
handle open took it to 0.14 ms — a 100× improvement on the hot path, found by
measuring rather than by reading the code.

## 3. Compatibility

*Co-existence, interoperability.*

| Sub-characteristic | Evidence |
|---|---|
| Co-existence | Cop and thief run on one machine on separate ports (8802/8801) with independent workspaces. |
| Interoperability | Verified against the **course reference simulator**, not only against ourselves: all four tools exchanged in both directions, and our `commit_of` reproduces the reference's signature byte for byte (`tests/goldens/`). |

This is the characteristic the project failed hardest and learned most from.
The reference names the MCP tool argument `message` on three tools and `payload`
on one; we sent `payload` to all four. **Every message was rejected by argument
binding before a byte of game logic ran, in both directions**, and every one of
our own tests passed throughout.

## 4. Usability

*Learnability, operability, error protection, aesthetics, accessibility.*

| Sub-characteristic | Evidence |
|---|---|
| Learnability | `docs/RUNBOOK.md` is written to be followed literally under time pressure with an opponent waiting. `README.md` carries a troubleshooting table of symptoms actually hit. |
| Operability | One command per task; `scripts/pre_match_smoke.py` answers "are we ready" in ~50 s with a single `MATCH READY`. |
| Error protection | CLI exit codes distinguish *ran and the answer was bad* (1) from *could not run* (2) — an audit verdict must never be mistaken for a typo. `preflight` refuses to report ready on an empty opponent URL. |
| Aesthetics | Dashboard heuristics documented against Nielsen's ten in `docs/UX.md`. |
| Accessibility | Charts never rely on colour alone — hatching and markers carry the same distinction, asserted in `tests/unit/test_analysis/test_charts.py`. Dashboard contrast and keyboard navigation in `docs/UX.md`. |

## 5. Reliability

*Maturity, availability, fault tolerance, recoverability.*

| Sub-characteristic | Evidence |
|---|---|
| Maturity | 180 consecutive games with zero peer disagreements and zero audit failures (`notebooks/analysis.ipynb` §4). |
| Availability | A named Cloudflare tunnel keeps its hostname across restarts, so the opponent's saved URL survives a crash (`test_chaos_services.py`). |
| Fault tolerance | Total outage of both paid LLM providers falls through to a zero-token template floor and the game continues. A Gmail 429 storm parks the report rather than hammering the mailbox. |
| Recoverability | Every artifact is written before it is sent; a dead letter is recoverable, a missing artifact is not. Deadlines use `time.monotonic`, so an NTP correction cannot move one. |

⚠ **Known gap.** A two-process series does not complete unattended
(`docs/OPEN_ITEMS.md`). Messages are accepted — 101 accepted, 395 deadlines
started, 101 met — and the peers still wait each other out. In-process over real
MCP the same series is correct. This is the reliability claim we cannot yet make.

## 6. Security

*Confidentiality, integrity, non-repudiation, accountability, authenticity.*

| Sub-characteristic | Evidence |
|---|---|
| Confidentiality | Nonces are secret until reveal (rule 18). A meta-test scans every outbound payload shape for forbidden keys — `opponent_position`, `nonce`, and friends (`sdk/queries.py:FORBIDDEN_KEYS`). A CI gate fails the build if a secret is ever tracked. |
| Integrity | SHA-256 commit-reveal over canonical JSON; a mismatch at reveal voids the game for the party whose records fail to re-hash (rule 19). `tests/goldens/artifacts/log_tampered_step7.json` proves the audit still bites. |
| Non-repudiation | Terms are signed with a SHA-256 over the canonicalised contract; the handshake refuses to play on mismatch. |
| Accountability | Every meaningful action is an event-sourced JSON line; the replay viewer re-derives a whole match from the log. |
| Authenticity | Prompt-injection defences: an opponent's free text is sanitised and fenced before it reaches a model, and a suspicious hint has its extracted confidence discounted (`tests/unit/test_llm/test_injection_guard.py`). |

`docs/SECURITY.md` holds the threat model. The boundary that matters most is
stated in `docs/EXTENDING.md`: plugin paths are read from local config only,
never from anything the opponent sends — the opponent is explicitly permitted to
lie to us.

## 7. Maintainability

*Modularity, reusability, analysability, modifiability, testability.*

| Sub-characteristic | Evidence |
|---|---|
| Modularity | Book rule 3 enforced structurally: peripheral packages never call each other, only the orchestrator (`docs/PLAN.md` §1.3, asserted in `tests/unit/test_net/test_architecture_rules.py`). |
| Reusability | The core package is **byte-identical** across both repos, checked by `scripts/sync_core.py` as a test — it caught two unsynced files during E21. |
| Analysability | Event-sourced logs; 17 ADRs recording *why*; `docs/OPEN_ITEMS.md` recording what is incomplete with its evidence. |
| Modifiability | Four documented extension seams with a worked, tested plugin (`docs/EXTENDING.md`). |
| Testability | Every component is built against a protocol, so each is testable against a fake — the seam Assignment 6 never had. ≤120-line file budget keeps units small enough to test. |

The honest caveat on testability: fakes are only as good as the assumptions in
them, and ours were wrong three times. Meta-tests now assert the *fakes* match
the real classes they stand in for.

## 8. Portability

*Adaptability, installability, replaceability.*

| Sub-characteristic | Evidence |
|---|---|
| Adaptability | Developed on WSL2; CI runs on Linux. Paths via `pathlib`, no shell assumptions. The event log holds its handle open specifically because Windows-mounted filesystems are slow. |
| Installability | `git clone && uv sync && uv run python scripts/check_all.py`. One lockfile, one command, one verdict. |
| Replaceability | Adapter profiles absorb an opponent's protocol deviations without touching the transport (ADR-011). |

⚠ macOS is untested. Nothing in the code should prevent it, but "should" is not
evidence, and this row says so rather than claiming a platform we never ran on.
