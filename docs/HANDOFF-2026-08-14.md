## 3. Running a match

Run **one repo** for the whole series; it alternates roles internally. Which repo
you run decides only which side you *open* on. The thief opens every sub-game.

```bash
# 1. card (writes into BOTH repos)
uv run python scripts/match_day.py card --team <name> --url <their-url> \
    --group-id <their-exact-group-id>

# 2. arm
uv run python scripts/match_day.py warmup     # sandbagged + draft  <- friendlies
uv run python scripts/match_day.py counted    # full + send         <- counted only

# 3. tunnel, own terminal, left running (8802 cop / 8801 thief)
cloudflared tunnel run --url http://127.0.0.1:8802 najamjad-cop

# 4. preflight, then play
uv run najamjad-cop preflight --opponent <name> --practice
uv run najamjad-cop match --opponent <name> --no-tunnel --practice \
    --talk --dashboard --dashboard-host 0.0.0.0

# counted: drop --practice and --dashboard-host
```

**`match_day.py archive --team <label>` before every rerun.** `game_id`,
`game_uid` and every filename derive from the two group ids and the terms, so a
second series against the same opponent silently overwrites the first.

### Signs that look like failures and are not

| Sign | Meaning |
|---|---|
| Long silence between sub-games | A peer rebinding a fresh process. `handshake_retries = 8` ≈ 6 min. **Do not Ctrl-C** |
| `client.session_dropped` | The §4.2 fix firing, once per boundary, before the handshake |
| `Session termination failed: 502` | Harmless SDK warning from that drop |
| `502` on our door with no agent up | Tunnel alive, agent not started. `406` is healthy |
| Dashboard unreachable from Windows in a **counted** run | Deliberate — counted binds loopback (rules 8-9). Open it inside WSL |

### 5.2 Receiver-side scent decay (parked deliberately)
imreeyal transmit **post-decay** and decay on receipt; we transmit **pre-decay**,
so ours nets exactly one decay in their field — correct. Theirs ages **twice** in

### 5.5 The capture claim — **settled, 2026-08-14, by measurement**
Closed. A capture claim **is** read as a fix on the cop's own cell, and the two
earlier removals were wrong. The reasoning and the numbers live in
`cop_sighting.from_claim`; `uv run python scripts/claim_evidence.py` re-runs all
of it in about a minute.

**Semantics, settled from the senders rather than from our receiver.** Both
removals argued from `answer_capture_claim(true_thief_cell, claimed_cell)`, and
that argument is void: the answering line is identical whether the cop is
reporting its own cell or guessing at ours, so the receiver cannot settle what
the sender meant. The senders can. Both reference repos send
`list(rt.state.position)` on every police *move*; our own cop is locked to its
own true cell by T-0535; and **323 of 323** sealed claims in every archive name
the claimer's own revealed position — 306 from uoh-ay26 alone.

**Outcomes, on uoh-ay26's own recorded lines with their real declarations at the
steps they were really declared on.** Ignoring claims: belief wrong by 2.04
cells on average, exact on 10% of turns, and **g03 lost to a capture at step
26**. Reading them: exact every turn, both games survived. Gated by
`tests/regression/test_claim_evidence_on_a_real_line.py`, which asserts the
counterfactual too.

**The recorded harm was real and is now understood.** It was a fusion
interaction, not a semantic one — exactly as suspected. A claim on *our own*
cell put 0.99 on our square for the turn's closing `exclude()` to delete, and on
the way past it evicted the barrier sighting for that turn under
`_record_sighting`'s exact-beats-inexact rule. Dropping such a claim before it
is held restores the ignoring behaviour precisely (2.04 either way, against 3.73
unguarded), so the free blinding attack now buys nothing.

**What is still exposed, stated plainly.** A peer that lies *consistently* —
naming a cell one row from where it stands, every turn — degrades us, and on the
uoh-sqak sweep turns 35/35 into a capture at step 14. Three guards were tried
and measured and **none of them work**: anchoring `plausible` on the signed
`cop_start`, refusing rather than downgrading an implausible claim, and widening
the own-cell guard to the surrounding ring (that one was strictly worse — it
re-lost g03 while holding a near-perfect belief, by discarding the claim exactly
when the cop was adjacent). We carry the exposure because it needs a peer to lie
about its own position on the wire, which has never once happened, and because
`verify_trail` now checks every claim against their revealed records — so a peer
that starts doing it leaves the evidence in our own archive.

Two side findings from the same work, both fixed:
* a **thief** peer could inject a phantom into our cop's belief by sending a
  `capture_claim`. Police-only declaration; now gated on the role.
* `run_duel` took a *dense* one-wall-per-step barrier list, which cannot express
  "no barrier this turn". `AMJAD_G02_BARRIERS` therefore reads as steps 1-4 where
  the archive says 9, 11, 16 and 18 — a peer walling cells it could not have
  reached. It now accepts `{step: cell}`, and archived lines use that.

Found while preparing the vibecode series, and it would have gone out on the
wire that night. `najamjad-cop` declared **1** counted match; `najamjad-thief`
declared **2**. Both were honestly written: a series is played from *one* repo —
whichever role we open on — and only that repo's tracker is written at
settlement. Both counted series were opened as thief, so the cop repo never
learned about either imreeyal or, in its `opponents_already_counted` list, the

`counted_games_played: 1` and `opponents_already_counted: ["uoh-ay26"]` —
contradicting imreeyal's already-filed artifact. Rule 38 judges this figure on
mutual consistency between the two teams' files and treats a false declaration
as project-level. This is the same defect class as §4.6, and this time it was
ours.

* **Reconciled**: both repos now declare 2, verified through
  `tracker_for().declaration()` rather than by reading the file.
* **Nothing was typed.** `scripts/reconcile_counted.py` merges the two
  machine-written ledgers by `game_uid` through the tracker's own `record()`,

* **It cannot drift silently again**: `counted_ledger_check` is in the standard

  be changed by something that runs automatically before every match. A missing

* **Run `scripts/reconcile_counted.py ../<sibling> --apply` after every counted

Checked at the same time, since both repos must play at the same strength: the

## 6. Conventions agreed in writing

- **`mutual_agreement.sha256`** = sha256 over `{game_id, aggregate, sub_games[
  sub_game_number, roles, result, winner_group, score]}`, sorted keys, raw UTF-8,
  **spaced separators**. Byte-equal on both sides. Reproduced against imreeyal.
- **`tokens_total_series`** is per-side: own spend, **zero** for the opponent.
- **Diversity reward** derived: counted AND first meeting AND this group won.
  Crowns whoever won. `total_score` stays the pure sub-game sum.
- **Mail:** body = the attachment's **exact bytes**. Subject:
  `Police-Thief series result: winner <group_id> (reported by <role>)`.
- **Friendly** reports to the opponent and ourselves, **never** the lecturer.
  **Counted** to `rmisegal+uoh26finalgame@gmail.com` **alone**.
- **T protocol:** both holding by T−10, curl at T (406 = ready), explicit "go"
  each side, then dial. Not 406 by T+30s → new T. Never debug inside a window.

## 7. Discipline that has already saved us

- **Freeze before declaring a hash.** `git status` empty, then `git rev-parse
  HEAD`, then send the **full 40 characters**. A team blocked their own
  submission over a 7-char hash.
- **Arming is sticky.** `counted` leaves `send` + `full` in *tracked* config.
  Disarm afterwards or the next warm-up plays at full strength and the next
  practice mails whoever `practice.redirect_to` names. Found in the wrong state
  once already.
- **`practice.redirect_to` is practice-mode-only.** A counted run ignores it and
  routes to the configured lecturer address. Verified, not assumed.
- **Archive before every rerun.**
- **Verify a finished series**: `replay` every log, the kit's
  `tools/check_artifacts.py --terms`, and compare against the opponent's file
  *before* anyone files.
- **The two-process harness writes to a `TemporaryDirectory` deleted on exit.**
  Its events are gone before you can read them — never use it to prove an event
  fires. Drive `MatchRunner` in an integration test instead.

## 8. The one habit worth keeping

**Five components this week existed, passed their own tests, and were never
called**: the artifact writer, the reconciler, the session guard, the thief's
strength dial, and `cop_sighting.from_claim`. Several more were properties we had
asserted in writing and never measured — the declared scent form, the agreement
digest construction, the count key name, two preflight checks, and "they send no
hints" (measured from *sealed records*, which structurally cannot carry hints in
their build).

Reading the call site and believing it is not verification. The question that
found all of them is:

> **Does this actually reach anything, and how would I know?**

Answer it by feeding the real thing through the real path and watching the output
change — not by reading the code and reasoning that it should.
