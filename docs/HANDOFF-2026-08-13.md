## 3. Running a match

Roles: `najamjad-cop` on port 8802, `najamjad-thief` on 8801. **Run one repo for
the whole series** — it alternates roles internally. Which repo you run decides
only which side you *open* on; the thief opens every sub-game.

```bash
# 1. opponent card (writes into BOTH repos)
uv run python scripts/match_day.py card --team <name> \
    --url <their-url> --group-id <their-exact-group-id>

# 2. arm
uv run python scripts/match_day.py warmup     # sandbagged + draft   <- friendlies
uv run python scripts/match_day.py counted    # full + send          <- counted only

# 3. tunnel, in its own terminal, left running
cloudflared tunnel run --url http://127.0.0.1:8801 najamjad-thief

# 4. preflight, then play
uv run najamjad-thief preflight --opponent <name> --practice
uv run najamjad-thief match --opponent <name> --no-tunnel --practice \
    --talk --dashboard --dashboard-host 0.0.0.0

# counted: drop --practice and --dashboard-host
uv run najamjad-thief match --opponent <name> --no-tunnel --talk --dashboard
```

**`match_day.py archive --team <label>` before every rerun.** `game_id`,
`game_uid` and every filename derive from the two group ids and the terms, so a
second series against the same opponent silently overwrites the first. This
nearly cost the uoh-ay26 counted evidence.

### Things that look like failures and are not

| Sign | Meaning |
|---|---|
| Long silence between sub-games | A peer with a fresh process per sub-game is rebinding. `handshake_retries = 8` gives ~6 min against a gap measured at 131 s. **Do not Ctrl-C.** |
| `client.session_dropped` at a boundary | The fix in §4.2 firing, once per sub-game, before the handshake |
| `Session termination failed: 502` | Harmless SDK warning from that same drop — we are closing a session to a peer that has already torn down |
| `502` on our own door with no agent running | Tunnel alive, agent not started. `406` is the healthy answer |
| Dashboard unreachable from Windows in a **counted** match | Deliberate: counted binds loopback (rules 8-9, the panel renders our belief grid and sealed state). Open it inside WSL |

## 4. What was fixed this week, and why it matters

Every one of these was found by an opponent's review or by measuring something
we had asserted. The pattern is the lesson: **a property nobody measured is a
property we do not have.**

### 4.1 The role-split retarget (newest, untested against a live peer)
We retargeted to the opponent's per-role endpoint only *after* the handshake.
Against a two-process peer, sub-game 2's negotiate would go to the process
playing the role they had just finished. Now retargeted *before* the exchange,
using the identity declared last sub-game. **vibecode is the first opponent this
can matter against — watch sub-game 2 closely.**

### 4.2 The dead socket at every sub-game boundary
We held one MCP session across the series. A peer running a fresh process per
sub-game leaves that socket attached to a process that no longer exists, so every
call hangs to the per-call cap while a bare `curl` reads a healthy 406 off their
*new* process. Cost a full friendly. Fixed by dropping the session before each
handshake.

### 4.3 The session-guard race
The guard pins `expected_sender` to the opponent's role for the sub-game, and we
bound it *after* the handshake returned. A fast opener lands in that gap and is
refused as `sender 'thief' is not the negotiated opponent 'police'`. Killed
sub-games 2, 4 and 6 three nights running. Now bound from role parity **before**
the exchange.

### 4.4 The agreement digest matched nobody
`mutual_agreement.sha256` exists to be byte-identical on both machines. Ours
hashed `{game_id, game_uid, groups, sub_games}` compact; the reference signs
`{game_id, aggregate, sub_games}` **spaced**. Two deviations, either sufficient.
Now reproduces imreeyal's published digest byte for byte. See §5.1 for the
consequence on our first counted series.

### 4.5 `counted_games_played`
We declared the count under `counted_matches_played`; the league's readers look
for `counted_games_played`. An honest opponent's report therefore carried
`najamjad: 0` against a truth of 1. Now sent under **both** spellings from one
tracker.

### 4.6 `winner_group` was never relabelled
`total_score` and `sub_games_won` are mapped from the tracker's internal `"them"`
placeholder onto the real group id; the winner was not. **It only bites on a
defeat** — five straight wins is why nothing showed it.

### 4.7 The cop had no strength dial
`ThiefBrain` sandbagged; `CopBrain` had no such field, so every "sandbagged"
warm-up played our real cop policy in three of six sub-games. Reduced strength is
now naive pursuit, no barriers, 3x claim bar. **Measured caveat:** across 49
position/peak pairs the two levels pick a different *move* only 3 times — on a
7x7 board every sane pursuit walks at the peak, so the weakening lives in
barriers and claims, not movement.

### 4.8 Two preflight checks reported green without checking
`authorise_gmail.py --check` reported a revoked token as fine (it read whether a
refresh-token field existed rather than trying it). `tunnel_check` returned the
configured hostname unchanged under a docstring claiming it confirmed a live
endpoint. Both now do the thing they claimed.

## 5. Open items

### 5.1 The uoh-ay26 agreement digest — the one real risk
Both teams' reports for counted series #1 **agree on every game fact**: all six
sub-games' roles, results, winners and scores, 90-30, 6-0, one shared `game_uid`,
`confirmed: true` both sides. Only `mutual_agreement.sha256` differs — and theirs
reproduces **neither our old construction nor the reference's**, so three
implementations gave three answers.

Rule 35 voids a match for *contradictory reports*. These contradict on nothing;
the digest is the mechanism for proving agreement and the mechanism differed
while the agreement held. **The book defines no remediation procedure** — no
amendment path, no re-file protocol. Verified, not assumed.

**Mitigation, and it is the reason vibecode matters: play a third counted
series.** At 3 counted, the worst reading of uoh-ay26 still leaves us at 2 and
above the threshold. That is entirely within our control; a favourable ruling is
not. Also worth telling uoh-ay26 what we found.

### 5.2 Receiver-side scent decay (parked, deliberately)
imreeyal transmit **post-decay** and their receiver decays on receipt; we
transmit **pre-decay**, so our trail nets exactly one decay in their field —
correct. Theirs ages **twice** in ours, because we decay an already-decayed grid.
Their suggested fix — skip our receipt decay — is **wrong for our code**: our
`absorb` max-merges, so without also replacing rather than merging, their trail
would never fade at all. Measured: with the extra decay our estimate tracks their
current cell; without it, it sticks to where they were first seen. **Do not ship
the naive version.** Doing it properly means replacing their field per frame.

### 5.3 Hints extract nothing from a landmark-only peer
`parse_locally` reads compass words. Across 102 imreeyal hints, **0 parsed as
informative**. Their landmarks leak position strongly — "Hell's Kitchen" appeared
42 times and every time they were in column 0-1 — and we discard all of it. The
largest free signal currently unused. Fit it to data from more than one opponent
before relying on it.

Separately, a place name containing a compass word ("East Village") parses as a
direction claim. Real, but it never fired against imreeyal.

### 5.4 A flaky test
`tests/integration/test_series_survives_a_stall.py::test_a_storm_costs_at_most_
the_game_it_hits_and_the_one_after` fails under CPU contention (both repos'
suites in parallel) and passes 8/8 in isolation. Timing-based, pre-existing.
**Re-run rather than chase it** — but only after confirming nothing else is red.

## 6. Conventions agreed with opponents, in writing

These are load-bearing and were each settled after a disagreement:

- **`mutual_agreement.sha256`** = sha256 over `{game_id, aggregate, sub_games[
  sub_game_number, roles, result, winner_group, score]}`, sorted keys, raw
  UTF-8, **spaced separators**. Must be byte-equal on both sides.
- **`tokens_total_series`** is per-side: each team reports its own spend and
  **zero** for the opponent. A zero means "not ours to attest".
- **Diversity reward** is *derived*, not claimed: counted AND first meeting AND
  this group won. It crowns whoever won, opponent included. `total_score` stays
  the pure sub-game sum.
- **Mail:** body must be the attachment's **exact bytes**, not a
  re-serialization. Subject is the reference's verbatim form:
  `Police-Thief series result: winner <group_id> (reported by <role>)`.
- **Friendly reports** go to the opponent and ourselves, **never** the lecturer.
  **Counted** goes to `rmisegal+uoh26finalgame@gmail.com` **alone**.
- **T protocol:** both holding by T−10, both curl at T (406 = ready), an explicit
  "go" from each side, then dial. Not 406 by T+30s → kill and name a new T. Never
  debug inside a window.

## 7. Match-day discipline that has already saved us

- **Freeze the code before declaring a hash.** `git status` empty, then
  `git rev-parse HEAD`, then send the **full 40 characters** — a 7-char hash does
  not match what the handshake declares, and a team blocked their own submission
  over exactly that.
- **Arming is sticky.** `match_day.py counted` leaves `send` + `full` in tracked
  config. After a counted series, disarm — otherwise the next warm-up plays at
  full strength and the next practice mails whoever `practice.redirect_to` names.
  This was found in the wrong state today.
- **`practice.redirect_to`** is a practice-mode-only override; a counted run
  ignores it entirely and routes to the configured lecturer address. Verified.
- **Archive before every rerun.** See §3.
- **Verify a finished series properly**: `replay` every log, run the kit's
  `tools/check_artifacts.py` over the artifact directory with `--terms`, and
  compare our result against the opponent's *before* anyone files.
